## 1. Executive Summary & Problem Statement

In previous iterations of EvolveLoop (v2.1 through v2.2), AI agents spent an average of **20,000 to 45,000 input tokens per task** performing indiscriminate, repetitive file reads (`read_file`, `cat`, recursive grep). This behavior was exacerbated by a fragmented landscape of **16 disparate knowledge and memory components**:
- Canonical project documentation in `.ai/pages/*.md` managed by Python scripts (`carpaccio.py`).
- Global organizational knowledge in an external vault (`$WIKI_ROOT`) accessed via a separate Python subprocess CLI (`gaabwiki`).
- Code syntax topology queried through a 7.4 MB static graph file generated by a third-party virtual environment binary in `/tmp` (`graphify`).
- Orphaned TypeScript storage layers (`FilesystemKnowledgeStore`, `FilesystemMemoryStore`).
- Subprocess IPC latency overhead of 1.6s to 2.5s per query.

The **Unified Knowledge System (UKS Core)** unifies these disparate components into a **single, local-first, native TypeScript knowledge engine** with sub-100ms retrieval latency, strict project scope isolation, and mathematical authority enforcement (`TruthFence`).

### Central Recommendation: Alternative B (Unified Engine with Native Scopes)
After formal evaluation of three architectural alternatives:
1. **Alternative A (Facade Wrapper):** Preserves legacy Python scripts under a TypeScript adapter. *(Rejected: Retains IPC latency, high cold-start overhead, and manifest divergence).*
2. **Alternative B (Unified Engine with Native Scopes — RECOMMENDED):** Consolidates indexing, tokenization, BM25 retrieval, AST syntax extraction, and TruthFence authority into a native TypeScript runtime under `orchestrator/src/knowledge/uks/`, keeping Markdown files in Git as the Single Source of Truth (SSOT) and derived indices in `.data/project-index.json`. *(Accepted for PoC & Target Architecture).*
3. **Alternative C (Vector/Graph Monolith):** Adopts an external daemon or embedded binary database (e.g. LanceDB/Neo4j). *(Rejected: Violates local-first, zero-external-dependency, and human-readable Git tracking principles).*
